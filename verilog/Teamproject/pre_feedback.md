# 10/19 교수님 피드백 정리

## 1. 설계 기준·사양의 근거

> 수치만 적으면 납득이 안 된다. Spec(sampling frequency 등)을 정했다면 반드시 합당한 이유가 있어야 한다.

- [ ] **100MHz**: 시스템 클럭으로 쓴 기준이 설명되지 않았다.
- [ ] **100Hz**: tick 주파수로 고른 이유를 고민해 볼 것.
- [ ] **Debouncer 4kHz**: 이 주파수를 고른 이유를 설명할 것.
- [ ] **입력값 범위**: 테스트 입력(12:59 / 12:55 / 23:30)을 왜 그렇게 골랐는지, 더 자세히 고민할 것.
- [ ] **입출력 사양**: 어떤 기준으로 정했는지 밝힐 것.
- [ ] **슬라이드 제목**: 제목에도 근거가 있으면 좋다.

## 2. 검증

- [ ] Expectation(예상 동작)이 빠졌다. 아래 흐름으로 정리할 것.
  > **Input → Checklist → Expectation → Result**
- [ ] Expectation대로 구현됐는지가 드러나야 한다.
- [ ] 검증 결과는 "~이다"처럼 **숫자로** 단정해서 쓸 것.
- [ ] 파형은 **x축과 y축을 표시**하고, 필요한 부분을 **확대**해서 보여줄 것.

## 3. 트러블슈팅

- [ ] 아래 흐름으로 정리할 것.
  > **현상(한 줄) → 원인 → 해결 → 적용(실제 Before / After) → 결과**

## 4. 슬라이드(장표) 작성

**메시지**
- [ ] 슬라이드마다 무엇을 말하는지 **한 줄로** 쓸 것. (지금은 무슨 말인지 모르겠다는 평)
- [ ] 장표 하나에 하나로 정리할 것.
- [ ] 결과와 고찰을 나눠서, 어디가 결과(결론)이고 어디가 고찰인지 보이게 할 것.

**레이아웃**
- [ ] 슬라이드가 꽉 차 있다. 텍스트 위주로 만들지 말고 간결하게 쓸 것.
- [ ] 전체적으로 글자를 키울 것.
- [ ] 블록 다이어그램의 범례(legend) 글자가 작다.

**누락**
- [ ] 핀 매핑(Pin mapping)이 없었다.

> 연습할 것: **한 줄로 쓰기**, 장표 작성 능력

## 6. 제출

- [ ] 파일명 형식: `이름_프로젝트명`
