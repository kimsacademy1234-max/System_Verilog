## 1. 왜 TB에 "검사기"를 만드나

- 지난번 시뮬레이션: 버튼 → TX 출력을 **눈으로** 파형 확인
- 오늘 목표: TB 안에 소프트웨어 수신기를 만들어 **보낸 값 = 받은 값** 자동 판정
  - 같으면 PASS, 다르면 에러 메시지 출력
  - start / stop / baud rate 에러 종류까지 자동 검사 가능
- 검증 방법 두 가지
  - **SW 검사기**: TB 안에서 baud time 계산해 직접 샘플링 → 설계가 덜 됐어도 타이밍 틀어짐 측정 가능
  - **HW 송수신**: TX·RX 둘 다 만들어 서로 주고받기 → 설계가 다 됐을 때 가능
- 확장 아이디어: 노이즈 주입, 클럭 주기 흔들기(5ns → 4.5/5.5ns), 패턴 변경, 미사용 로직 검출
  - 이를 표준화·자동화한 것이 **UVM**

### 전수 검사 vs 경계값
- 8bit 데이터 = 256가지 + start/stop bit 일부러 깨뜨린 에러 케이스까지 조합
- 랜덤 패턴 전송 → 특정 값/특정 비트 위치에서만 나는 버그 검출
- 사람이 하는 검증은 정상 1~2개 + **경계값**만 확인 (규칙적으로 동작한다는 가정)
- 비트 폭이 32bit 등으로 커지면 수작업 전수 검사 불가 → **프로그램으로 검사** = UVM의 존재 이유

## 2. task vs function

| 구분 | function | task |
|---|---|---|
| 반환 | return 값 있음 | 없음 (output 포트 사용) |
| 출력 포트 | 없음 | 있음 (모듈 포트처럼) |
| **시간 제어** (`#`, `@`, `wait`) | **불가** | **가능** ← 결정적 차이 |
| 용도 | sin/π 같은 순수 계산 | 시간 흐름이 필요한 동작 |

- RX 검사기는 **일정 시간(baud time)마다 delay 주며 읽어야** 하므로 → **task**
- 교수님은 Verilog에서 function 거의 안 씀 (task로 다 가능, 개인 스타일)
- task는 자기 모듈 안 변수에 직접 접근 가능 → 인자 생략 가능

## 3. TB 수신 task (TX 출력 검사기)

### 3-1. 샘플링 시점: 왜 비트 중앙인가
- UART는 **클럭(동기 신호)이 없음** → 아는 건 TX 신호와 시간뿐
- 데이터가 바뀌는 **transition 근처**에서 읽으면
  - 실제 HW: **메타스테이블** 발생 가능
  - start bit / bit0 / bit1 구분이 흔들림
- **중앙**에서 읽으면 가장 안정적, 송신 쪽이 조금 당겨지거나 밀려도 문제없음
- 시뮬레이터는 시간이 완벽히 일정하지만 실제 HW는 아님 → 시뮬레이션 ≠ 실제
- 예시: TX에 start WAIT 없이 보냈을 때 같은 값이 가끔 다른 값으로 인식됨 → 첫 비트가 짧아져 수신 쪽 샘플 시점이 경계에 걸린 것

### 3-2. 타이밍 시퀀스

```
TX: ‾‾‾‾\____|_D0_|_D1_|...|_D7_|‾STOP‾
         ↑  ↑    ↑    ↑         ↑    ↑
     감지 1/2T  +T   +T  ...   +T   +T
          (start 확인) (D0)          (stop 확인)
```

1. `wait (tx == 0);` — start 감지
2. `#(BAUD_BIT_PERIOD/2);` → start bit 중앙에서 `tx == 0` 재확인
3. `for (i = 0; i < 8; i++)` : `#(BAUD_BIT_PERIOD);` 후 `rx_data[i] = tx;` (**LSB부터**)
4. `#(BAUD_BIT_PERIOD);` → stop bit `== 1` 확인
5. 기대값과 비교 → `$display` PASS / FAIL (또는 `$error`)

- 방식 선택: "매 비트 1/2T + 1/2T" 대신 **처음만 1/2T, 이후 계속 1T** → 자동으로 계속 중앙 유지

### 3-3. `@(negedge tx)` 대신 `wait (tx == 0)` 쓰는 이유
- 버튼 누르자마자 TX가 이미 출발하면, task 호출 전에 **edge를 놓칠 수 있음**
- edge를 놓치면 다음 edge까지 무한 대기 → **시뮬레이션 멈춤**
- 타임아웃 탈출 조건 넣기 번거로우니 **레벨(0) 검사**로 안전하게

### 3-4. 실습 중 나온 이슈
- **edge를 이미 지나간 뒤 wait** → 영원히 안 걸림
  - DUT/TB 구성이 교수님과 달라 TX 신호가 task 호출 전에 끝나버린 경우
  - 해결: 모듈 내부 TX 신호를 **직접 참조**(hierarchical)해서 읽기
- **기대값 0x30인데 0x04 수신** → TB 문제가 아니라 **설계 미스**
  - 확인 순서: ① baud tick 주기 (1bit = **104.16 µs** 맞는지) ② state 전이
  - FSM을 data count 방식으로 바꾼 뒤 재검증 안 한 경우가 원인
- **Vivado 시뮬 재실행 불가**: 브레이크포인트 디버깅 중 멈추면 sim 디렉터리의 **`simulate.log`를 잡고 놓지 않음**
  - 해결: 시뮬 디렉터리에서 해당 log 파일 삭제 후 재실행 (지워도 무방)
- PASS/FAIL 출력은 **Tcl Console**에서 확인
- 디버깅: 소스에 브레이크포인트 → 한 줄씩 진행 가능 (교수님은 잘 안 씀)

## 4. 비동기 수신 이론 — 왜 16배 오버샘플링인가

### 4-1. 100MHz로 계속 감시하면?
- 장점: 중앙을 정확히 찾을 수 있음
- 문제: 외부 디바이스에서 날아오는 신호 → **노이즈 + 비동기 transition**
  - 매 클럭 읽을수록 transition/노이즈 순간에 걸릴 기회 증가 → **메타스테이블 확률↑**
  - 1bit 동안 샘플 수: 104.16 µs × 100 MHz ≈ **10,416번** *(계산)* vs 16배 tick이면 **16번**
- 메타스테이블 대응 원칙
  1. **발생 확률 자체를 낮춘다** → 필요한 순간에만 tick으로 샘플링
  2. 발생해도 받을 수 있게 → **synchronizer**(2-FF) 추가
- 교수님 경험: 확률만 낮춰도 synchronizer 없이 에러 거의 없음 (100%는 아님)

### 4-2. tick 배속과 틀어짐
- b_tick = baud tick × 1이면, RX 입력과 tick 위상이 안 맞음 → 중앙 보장 불가
- 배속을 올릴수록 start 감지 오차 감소

| 배속 | 최대 위상 오차 (1bit 대비) |
|---|---|
| ×1 | 최대 100% |
| ×2 | 50% |
| ×4 | 25% |
| ×8 | 12.5% |
| **×16** | **6.25%** |

- 배속↑ 단점: 메타스테이블 확률↑, 카운터 비트 수↑ (로직 증가) → **trade-off**
- 권장: **최소 8배 ~ 16배**, 8배는 다소 위험 → **16배로 설계**

### 4-3. TI MSP430 UART 앱노트 정리 (교수님 배포 자료)
- 구조: TX는 **PISO**, RX는 **SIPO**
- Common baud rate: 9600, 19200, 115200 …
- 일반적인 최대 baud rate 오차 허용: **2~3%**
- 16배 오버샘플 클럭 사용 (우리 16배 b_tick과 본질적으로 동일)
- 마진 계산
  - 이상적 마진 50% (비트 중앙)
  - − 16배 샘플링 오차 6.25% (1/16)
  - − rise/fall 오차 2%
  - = **실제 마진 41.75%**
  - 10bit 프레임 누적 고려 → 송·수신 각각 **±4.175%**까지 허용 *(계산: 41.75 / 10)*
- 틀어짐은 **비트마다 누적** → 마지막 비트에서 가장 커짐, 그래도 마진 안이면 OK
- 자료는 외부 배포 금지 (저작권)

## 5. 16배 b_tick 변경

- `F_COUNT = 100MHz / (9600 × 16)` ≈ **651** *(계산)*
- tick 주기 = 104.16 µs / 16 ≈ **6.51 µs** *(계산)* → 시뮬레이션에서 tick 간격 측정해 확인
- 이 변경 이후 기존 TX는 16배 빨라져서 틀어짐 → TX도 수정 필요

## 6. UART RX 설계

### 6-1. 상태
**IDLE → START → DATA → STOP → IDLE**

| 상태 | 동작 | 전이 조건 |
|---|---|---|
| IDLE | b_tick마다 rx 확인 | `b_tick && rx == 0` → START |
| START | b_tick_cnt 0~7 카운트 (**8 tick = 1/2 bit**) | cnt == 7 → start 재확인 (`rx == 0`) → DATA, 아니면 IDLE/에러 |
| DATA | b_tick_cnt 0~15 카운트 (**16 tick = 1 bit**) | cnt == 15 → rx 샘플 & shift → bit_cnt == 7이면 STOP, 아니면 bit_cnt++ 후 DATA |
| STOP | 16 tick 카운트 | cnt == 15 → `rx == 1` 확인 (아니면 frame error) → rx_done 펄스, IDLE |

### 6-2. 설계 포인트
- 카운트는 **0부터** → 8개면 0~7, 16개면 0~15
  - bit_cnt 0~7은 **3bit** (8로 세면 4bit 필요)
- 읽는 순서: **16 tick 카운트 → 읽기 → bit_cnt 처리** (증가 먼저 하면 안 됨)
- 수집 구조: **SIPO shift register**, LSB부터 들어옴
  - 예: `rx_data_next = {rx, rx_data_reg[7:1]};`
- 카운터 초기화: 상태가 넘어갈 때마다 b_tick_cnt를 0으로 (START 진입, START→DATA, DATA 비트마다, DATA→STOP)
- STOP 처리 선택
  - 16 tick 끝까지 가서 판정, 또는
  - stop bit 중앙에서 판정 후 바로 IDLE로 빠져 **다음 프레임 준비** (교수님 선호)
- 출력
  - **rx_done**: 수신 완료 시점에 **1 tick 펄스** (CPU/후단 로직에 알림)
  - "수신 중(busy)" 신호는 RX에선 중요도 낮음 (넣어도 무방)
  - 에러 신호: start/stop 검사 실패 시 띄움

## 7. UART TX 수정 (16배 tick 대응)

- **WAIT 상태 제거**: tx_start → IDLE에서 바로 START
  - 이유: 최대 1/16 bit(6.25%) 일찍 시작해도 **최초 1회만** 발생, 누적 아님 → 수신 측 문제없음
- b_tick_cnt 추가 (16 tick = 1 bit, 4bit 레지스터) → reset 초기화에도 추가
- 상태별 전이: 각 상태에서 `b_tick && b_tick_cnt == 15`일 때 다음 단계
- DATA: 16 tick마다 data reg 1bit shift, bit_cnt == 7이면 STOP
- STOP: 16 tick 후 IDLE
- **tx_busy**: START 진입 시 1, IDLE 복귀 시 0
- 공통 초기화(b_tick_cnt = 0)는 앞으로 빼서 중복 제거
- START → DATA 전이 시 카운터 초기화 누락 주의 (실습 중 빠졌던 부분)
- 체크: next/reg 뒤바뀐 곳 없는지, latch 생성 없는지 RTL 확인

## 8. Loopback 구성 (보드 검증)

### 8-1. Top (`uart.v`)
- 버튼 디바운서, LED 제거
- **RX → TX 직결 구조**
  - `rx_done` → `tx_start`
  - `rx_data[7:0]` → `tx_data`
- tx_busy 대기 불필요 (컨트롤러 없이 받는 즉시 보내는 구조)

### 8-2. XDC
- USB-UART **RX/TX 핀 주석 해제**
- 버튼은 **reset만** 남기고 주석 처리, LED 주석 처리, clock 유지
- Bitstream 생성 시 에러 없어야 함

### 8-3. 보드 테스트
- 장치 관리자에서 COM 포트 확인 → ComMaster로 open
- 1글자 보내면 1글자, 2글자면 2글자, **연속 데이터도 문제없이** 돌아와야 함 (ASCII 그대로)
- 글자가 깨지면 → **비트 밀림** → 시뮬레이션으로 원인 추적

## 9. Loopback TB

- DUT: loopback top, `rx`는 TB에서 구동하므로 **reg**, 초기값 **1** (idle)
- **sender task** (PC → FPGA RX 역할)
  1. `rx = 0;` → `#(BAUD_BIT_PERIOD);` (start bit은 **1/2이 아니라 1비트 전체**)
  2. 8번 반복: `rx = send_data[i];` → `#(BAUD_BIT_PERIOD);` (LSB부터)
  3. `rx = 1;` → `#(BAUD_BIT_PERIOD);` (stop)
- **receiver task**: 3장 검사기를 DUT `tx`에 연결
- 예: expected = `8'h30` 보내고 받은 값 비교 → Tcl Console에 PASS
- 파형에 추가할 신호
  - RX: state, b_tick_cnt, bit_cnt, data reg, rx_done
  - TX: tx_start, tx_busy, state, bit_cnt, b_tick_cnt, data reg, tx
- 실습 중 이슈: sender 쪽 포트 방향(output/input) 잘못 연결 → RX가 안 올라옴
