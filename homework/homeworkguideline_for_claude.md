#### 슬라이드 작성 규칙 (2026-10-05 사용자 피드백으로 확정 — 매번 지킬 것)

> 기준: 30년차 임원이 **딱 봤을 때 "아, 이런 식으로 잡아냈구나"** 가 보여야 한다

1. **쉬운 말 + 그림.** 제목만 읽어도 결론이 보이게 쓴다. 부가 설명은 최소화
2. **슬라이드에 코드 조각을 넣지 않는다.** 신호 이름(r_seen, w_bcd_sum…)이나 F1 같은 코드명은 그대로 쓰지 말고 쉬운 이름을 붙인다 (예: r_seen = "자리 체크표", 판정 = "채점", 버그 ①~⑤는 증상 이름)
3. **그림으로 보여준다** — 미니 FND 화면, 체크표가 채워지는 단계, ✓ 잡음 / ✗ 놓침 표시 등
4. **구조 설명은 2단:** 위에 실제 모듈 구성(코드 기준), 아래에 같은 번호로 쉬운 풀이
5. **"왜 그렇게 했는지"를 한 줄로 밝힌다** (예: 1 ms 대신 10 ns로 시뮬레이션한 이유 = 시간이 너무 오래 걸려서)
6. 사용자가 PPT를 직접 고친 부분(제목·문구·삭제·위치)은 다음 수정에서도 그대로 유지한다. 작업 전에 항상 최신 PPT와 직전 버전을 비교할 것

#### Verilog 파일 작성 규칙

- Claude가 쓰는 sim/source 파일은 **`homework/<프로젝트명>/`** (예: `homework/8bit_fnd_clk_project/`)의 `sim_file/`, `source_file/`, `fault/`에 둔다. 사용자 `vfile/`에는 쓰지 않는다
- 주석·$display까지 **영어(ASCII)만** 쓴다 — Windows Vivado 2020.2에서 한글이 깨짐
- `fault/`(결함 주입 사본)는 원본과 모듈명이 같으므로 Vivado 프로젝트에 넣지 않는다

#### 프로젝트 마무리 정리 절차 (매 프로젝트마다 동일 — 2026-10-05 사용자 지시)

1. 최종 PPT를 **PDF로 변환** (PowerPoint `SaveAs(..., 32)`), 사용자가 마지막으로 고친 PPT로 만든다
2. `homework/<프로젝트명>/` 폴더를 만들고 정리
   ```
   homework/<프로젝트명>/
   ├─ 정안성_(주제).pdf
   ├─ sim_file/     ← Claude가 만든 TB
   ├─ source_file/  ← Claude가 만든 RTL (있을 때만)
   └─ fault/        ← 결함 주입 사본 + 실행 스크립트 (Vivado 프로젝트에 넣지 말 것)
   ```
3. **코드와 PDF만 남긴다** — PPT 이미지·빌드 산출물(_build/, assets, 스크린샷, html 등) 전부 삭제. 최종 편집본 PPTX는 지우기 전에 사용자에게 확인 (이번엔 유지)
4. 정리가 끝나면 **중복 폴더 삭제** (예: 임시 `*_claude_vfile/`, `C:\Temp` 작업 폴더). 복사본이 원본과 같은지 확인한 뒤 지운다
5. Vivado 프로젝트가 옮긴 파일을 참조하고 있으면 새 경로를 사용자에게 알려준다
